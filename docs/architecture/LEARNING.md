# Closed-Loop Learning: Merchant Growth Autopilot

This document specifies the closed-loop learning and adaptation system, detailing the mathematical formulas, memory storage, and prompt injections used to alter future decisions.

## 1. Concept Overview
A core buildathon criteria is "genuine closed-loop adaptation." The system should not simply display performance reports; the outcome of a strategy must programmatically alter how the agent decides in subsequent runs.

```
       +------------------------------------+
       |       Goal & Context Request       |
       +------------------------------------+
                         |
                         v
       +------------------------------------+
       |  Fetch historical weights from SM  |
       +------------------------------------+
                         |
                         v
       +------------------------------------+
       |   Inject weights into prompt context|
       +------------------------------------+
                         |
                         v
       +------------------------------------+
       | Agent executes strategy selection  |
       +------------------------------------+
                         |
                         v
       +------------------------------------+
       |    Execute approved campaign       |
       +------------------------------------+
                         |
                         v
       +------------------------------------+
       | Measure actual vs predicted outcomes|
       +------------------------------------+
                         |
                         v
       +------------------------------------+
       | Calculate prediction error (e)     |
       +------------------------------------+
                         |
                         v
       +------------------------------------+
       |  Adjust and save weight to SM      |
       +------------------------------------+
```

## 2. Mathematical Adaptation Formula

When a campaign completes, the system pulls the actual telemetry data and calculates the **Prediction Error (\(\epsilon\))**:
\[\epsilon = \frac{|U_{\text{actual}} - U_{\text{predicted}}|}{\max(U_{\text{predicted}}, 0.01)}\]

Where:
- \(U_{\text{actual}}\): Actual conversion uplift achieved (e.g. 0.059 for 5.9%).
- \(U_{\text{predicted}}\): Predicted conversion uplift generated by the Simulator (e.g. 0.072 for 7.2%).

---

### 2.1 Underperformance Decay (Penalty)
If the strategy underperformed relative to projections (\(U_{\text{actual}} < U_{\text{predicted}}\)), we decay the strategy's weight modifier:
\[W_{t+1} = W_t \cdot e^{-\gamma \cdot \epsilon}\]

Where:
- \(W_t\): Active weight modifier in Strategy Memory (defaults to `1.0` on first run).
- \(\gamma\): Learning rate constant, locked at `0.5`.
- \(\epsilon\): The calculated prediction error.

*Example*: If predicted uplift was 10%, but actual was only 5%, error \(\epsilon = \frac{|0.05 - 0.10|}{0.10} = 0.5\).
\[W_{t+1} = 1.0 \cdot e^{-0.5 \cdot 0.5} = e^{-0.25} \approx 0.778\]
The strategy's select probability context is penalized by ~22%.

---

### 2.2 Overperformance Boost (Reward)
If the strategy meets or exceeds expectations (\(U_{\text{actual}} \ge U_{\text{predicted}}\)), we boost the weight:
\[W_{t+1} = W_t \cdot (1 + \min(0.20, 0.05 \cdot ROI))\]

Where:
- \(ROI\): The final return on investment.
- The reward multiplier is capped at a maximum of `1.20` (+20%) per iteration to prevent runaway positive feedback loops.

---

## 3. Database Persistence
Weights are persisted inside the `strategy_memory` MongoDB collection:
```typescript
interface StrategyMemoryDocument {
  merchantId: string;
  strategyType: 'payment_method_fallback' | 'cart_value_boost' | 'checkout_recovery';
  segmentKey: string;
  weightModifier: number; // Defaults to 1.0, updated via formulas above
  predictionErrorHistory: number[];
  roiHistory: number[];
  updatedAt: Date;
}
```

---

## 4. Prompt Context Injection (Closing the Loop)
During the cognitive planning phase of a new run, the agent orchestrator executes a lookup in `strategy_memory` for the active merchant:
```typescript
const historicalMemory = await StrategyMemory.find({ merchantId });
```
This payload is formatted into a clean markdown table and injected into the agent system prompt context:

```markdown
### SYSTEM MEMORY: HISTORICAL STRATEGY PERFORMANCE
You must use the following historical weight modifiers to guide your recommendations.
A weight < 1.0 indicates historical underperformance. Avoid recommending these unless no alternatives exist.
A weight > 1.0 indicates strong historical performance. Favor these strategies.

| Strategy Type | Target Segment | Current Weight | Last Prediction Error |
|---|---|---|---|
| payment_method_fallback | high_value_upi_users | 0.778 | 0.50 |
| checkout_recovery | abandoned_checkouts | 1.150 | 0.02 |
```

The system prompt explicitly commands the cognitive layer:
> "You must apply the weight multipliers to your qualitative strategy selection. If a strategy's weight is below 0.8, you must prioritize alternative strategies unless constraints make it the only option."
This directly enforces adaptation in future decision paths.
